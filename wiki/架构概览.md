# 架构概览

本页介绍 Getty 的整体架构设计，帮助你理解各层的职责与协作方式。

## 整体分层

```
┌──────────────────────────────────────────────────────────────┐
│                     用户业务代码                               │
│         继承 SimpleChannelInboundHandler 实现业务逻辑          │
├──────────────────────────────────────────────────────────────┤
│                  Pipeline 责任链层                             │
│   SSLHandler → Decoder → BusinessHandler → Encoder            │
│   入站: head → tail（next 方向）                               │
│   出站: tail → head（prev 方向）→ writeToSocket               │
├──────────────────────────────────────────────────────────────┤
│                  Channel 通道层                                │
│   AioChannel / NioChannel / UdpChannel                        │
│   统一 API: writeAndFlush / close / starRead                  │
├──────────────────────────────────────────────────────────────┤
│                  I/O 模型层                                    │
│   AIO: AsynchronousSocketChannel + CompletionHandler          │
│        + 共享写线程组（AioWriteThreadGroup）                    │
│   NIO: SocketChannel + Selector + NioEventLoop                │
│   UDP: DatagramChannel + Selector                             │
├──────────────────────────────────────────────────────────────┤
│                  内存管理层                                     │
│   三级池: PoolThreadCache → PoolArena → PoolChunk              │
│   零拷贝: slice / asByteBuffer / readArray                     │
│   引用计数: retain / release 自动归还                          │
└──────────────────────────────────────────────────────────────┘
```

## 核心组件

### 1. Starter（启动器）

Starter 是 Getty 的入口类，负责创建 I/O 通道、初始化内存池、启动线程模型。

| 类名 | 用途 |
|------|------|
| `AioServerStarter` | AIO 服务端启动器 |
| `AioClientStarter` | AIO 客户端启动器 |
| `NioServerStarter` | NIO 服务端启动器（也支持 UDP） |
| `NioClientStarter` | NIO 客户端启动器（也支持 UDP） |

所有 Starter 均支持链式调用配置：

```java
AioServerStarter server = new AioServerStarter(config)
    .channelInitializer(initializer)
    .writeThreadNum(4)
    .bossThreadNum(4);
server.start();
```

### 2. Channel（通道）

`AbstractSocketChannel` 是所有通道的抽象基类，屏蔽了 AIO/NIO/UDP 的底层差异：

- `AioChannel` — AIO 异步通道
- `NioChannel` — NIO TCP 通道
- `UdpChannel` — NIO UDP 通道

统一 API：

| 方法 | 说明 |
|------|------|
| `writeAndFlush(obj)` | 经管道编码后写出数据 |
| `write(obj)` | 经管道编码后追加到写缓冲区，不触发实际写出 |
| `flush()` | 刷新写缓冲区，触发实际写出 |
| `close()` | 安全关闭通道，触发监听器 |
| `starRead()` | 开始读取数据 |
| `getChannelPipeline()` | 获取责任链管道 |
| `getChannelAttribute()` | 通道属性绑定 |
| `isInvalid()` | 通道是否已关闭 |

### 3. Pipeline（责任链管道）

Pipeline 采用双向链表结构，分为入站和出站两个方向：

```
入站（读）:  head → Decoder → SSLHandler → BusinessHandler → tail
出站（写）:  tail → BusinessHandler → SSLHandler → Encoder → head → writeToSocket
```

- **入站事件**（连接建立、数据读取、连接关闭、异常、心跳）沿链表从头向尾传播
- **出站事件**（数据写入）沿链表从尾向头传播

### 4. Handler（处理器）

所有处理器实现 `ChannelBoundHandler` 接口，通常继承以下基类：

| 基类 | 用途 |
|------|------|
| `ChannelHandlerAdapter` | 通用基类，所有事件默认透传 |
| `ChannelInboundHandlerAdapter` | 入站处理器基类 |
| `ChannelAllBoundHandlerAdapter` | 双向（入站+出站）处理器基类 |
| `SimpleChannelInboundHandler<T>` | 泛型消息处理器（推荐业务层使用） |

事件回调方法：

| 方法 | 触发时机 |
|------|---------|
| `channelAdded(ctx)` | 通道建立，处理器加入管道 |
| `channelClosed(ctx)` | 通道关闭 |
| `channelRead(ctx, in)` | 接收到数据 |
| `channelWrite(ctx, obj)` | 写出数据（出站方向） |
| `exceptionCaught(ctx, cause)` | 发生异常 |
| `userEventTriggered(ctx, evt)` | 用户事件（如心跳空闲超时） |

### 5. 内存池

Getty 实现了三级内存池，借鉴 Netty 的 `PooledByteBufAllocator` 设计：

```
PoolThreadCache（L1 线程本地缓存）
    ↓ 未命中
PoolArena（L2 区域管理器）
    ↓ 未命中
PoolChunk（L3 二叉树内存块，默认 16MB）
```

- 同线程分配 ~0ns，无锁竞争
- 跨线程释放走 MPSC 无锁队列，~5ns CAS 延迟
- 二叉树 O(log N) 分配/释放，低碎片
- 引用计数 `retain/release` 归零自动归还池

### 6. I/O 线程模型

#### AIO 模型

```
┌──────────────────────────────────────┐
│  AsynchronousChannelGroup (Boss 线程池) │
│  负责 accept 连接事件                    │
├──────────────────────────────────────┤
│  CompletionHandler                     │
│  OS 回调驱动读取                        │
├──────────────────────────────────────┤
│  AioWriteThreadGroup (共享写线程组)      │
│  默认 4 个写线程管理所有 Channel 的写出    │
│  无数据时 park 阻塞，零 CPU 空转          │
└──────────────────────────────────────┘
```

#### NIO 模型

```
┌──────────────────────────────────────┐
│  Accept Thread (非 daemon)              │
│  负责 accept 连接事件                    │
├──────────────────────────────────────┤
│  NioEventLoop 池 (Worker 线程)          │
│  每个 EventLoop 管理一组 Channel          │
│  轮询 Selector 处理读/写事件              │
│  读缓冲区在 EventLoop 级别复用             │
└──────────────────────────────────────┘
```

## 数据流向

### 读取流程（入站）

1. 底层通道读取数据到 `PooledByteBuffer`
2. 调用 `invokePipeline(CHANNEL_READ, readBuf)` 从 head 开始正向传播
3. 经过 Decoder 解码（如 `StringDecoder` 将字节转为 String）
4. 到达 BusinessHandler 的 `channelRead0` 方法
5. 释放读取缓冲区

### 写入流程（出站）

1. 用户调用 `channel.writeAndFlush(obj)`
2. 调用 `reverseInvokePipeline(CHANNEL_WRITE, obj)` 从 tail 开始反向传播
3. 经过 Encoder 编码（如 `StringEncoder` 将 String 转为 `PooledByteBuffer`）
4. 到达 head 节点，调用 `writeToSocket` 写入底层通道
5. AIO 由共享写线程组异步写出；NIO 由 EventLoop 在 OP_WRITE 就绪时写出
